# TASK-0403 阅读器移动体验与视觉轻润色设计

## 1. 目的与边界

本设计服务于 `PHASE-04 / TASK-0403`：在不重做品牌、不改变阅读数据契约、不增加常驻复杂工具栏的前提下，使阅读器在手机和桌面上更安静、圆润、自然、单手易用，并修复已审计出的遮挡、焦点和触控缺陷。

本轮保留现有东方纸感、纸张主题、绿色强调色、正文排版设置和顶部/底部工具栏的功能组成。不重做书架与全局 AppShell，不引入新导航，不调整 AI 能力边界，不把动画当作质感补丁。

设计分类与参数：`[Taste: immersive reader + utility workspace | Dials: Variance 3, Motion 2, Density 4]`。

## 2. 已确认问题

1. 390×844 下，菜单显示时 fixed 顶栏和底部工具栏与正文保留空间不一致，分页末段、页码或连续滚动末段可能被遮挡。
2. 目录抽屉、设置 Sheet、进度 Sheet 只有视觉显隐，没有完整模态语义、初始焦点、焦点圈定、Escape 关闭和触发器焦点归还；隐藏工具栏仍可能进入 Tab 顺序。
3. 设置和进度控件存在 24–36px 的命中区，低于手机 44px 最小触控目标。
4. 同一工具层混用 emoji、Unicode 符号和 Lucide，图标字重、基线和跨平台渲染不一致。
5. 阅读器局部存在多套圆角、阴影、缩放和运动时长，交互反馈显得忽轻忽重；部分控件移除默认 outline 后没有统一 focus-visible 样式。

## 3. 推荐方案

采用“系统性轻润色”，而不是只修三个 P1 或整体换皮：先建立共享交互原语与阅读器视觉 token，再逐一接入现有 Reader 组件。这样既能消除可验证缺陷，也能让图标、文字、圆角、按压反馈和面板层级形成同一语言，同时保持改动可逆。

### 3.1 阅读器布局保留区

- 定义阅读器移动端顶部栏、底部栏、面板间距和安全区 CSS 变量，作为唯一几何来源。
- 菜单显示时，滚动正文使用与实际工具栏一致的内容 padding 和 `scroll-padding`；菜单隐藏时回到沉浸阅读留白。
- 分页测量与渲染使用同一组顶部/底部保留值，页码必须位于底部工具栏上方。
- 375px、390px、横屏和有/无 safe-area 环境均不得出现正文或主控被覆盖；不得通过永久增加大块空白掩盖遮挡。

### 3.2 共享模态行为

- 新增小型、无数据副作用的 Reader dialog/focus 工具，供目录抽屉、设置 Sheet、进度 Sheet 和已有阅读器弹层复用。
- 打开时记录触发元素；容器使用 `role="dialog"`、`aria-modal="true"` 和可读标题；焦点进入第一个合适控件或面板容器。
- Tab/Shift+Tab 在面板内部循环，Escape 关闭；关闭后焦点归还原触发器，若触发器已卸载则归还阅读 canvas。
- 背景阅读区和隐藏工具栏使用 `inert`/`aria-hidden` 退出交互与读屏树；不可只依赖 `pointer-events-none`。
- 不引入重量级 dialog 依赖，不改变现有 `activePanel` 状态模型。

### 3.3 触控与手势

- 所有手机按钮命中区至少 44×44px，相邻主控间距至少 8px；图标视觉尺寸维持 18–20px，避免按钮看起来臃肿。
- Range 滑块保留原生键盘语义，同时扩展触摸轨道命中区；拖动结束才提交跳转，拖动过程中只更新预览值。
- 目录抽屉保留可见关闭按钮；现有横向滑动关闭只能作为快捷方式，不能成为唯一出口，也不得阻断系统边缘返回手势。
- 阅读正文继续以垂直滚动或明确页控为主，不新增全屏横滑手势。

### 3.4 图标、文字与视觉层级

- 统一使用项目已有 `lucide-react`；同一工具层使用 18–20px、约 1.75–2px 的 outline 风格。移除 `✨`、`⚙`、`☾`、`⏮`、`◷` 等结构性 emoji/符号。
- 标准导航图标可单独使用但必须有 `aria-label`；非显然功能继续保留简短中文标签。AI 入口文案沿用“伴读”，图标不使用闪烁 emoji。
- 正文继续使用用户选择的楷/宋/黑字体；工具 UI 使用既有 `--font-ui`，章节标题使用 `--font-display`。不通过远程字体新增运行时网络依赖。
- 控件正文不小于 12px；主要标签采用 12–14px，说明与数值形成清晰的字重和颜色层级。文案避免“高级、优雅、智能”等自我评价词，只描述动作和状态。
- 阅读器面板统一控制圆角、边框和阴影：外壳 20–24px、分段控件 10–12px、图标按钮圆形或 12px；阴影仅表达浮层层级，不叠加多层发光。

### 3.5 动效

- 本轮不引入 GSAP。面板、菜单和按压反馈只使用 CSS transform/opacity，进入约 180–220ms，退出约 140–180ms；不动画 width/height/top/left。
- 去除无功能意义的 overshoot、长呼吸和重复缩放；按压反馈以颜色/透明度为主，必要时最多 `scale(0.98)`。
- `prefers-reduced-motion: reduce` 下取消位移、缩放和闪烁，仅保留即时显隐或极短淡变。
- 若后续真实回放证明章节切换需要跨组件同步、可中断时间线，才在新的受控设计决定中采用 GSAP。

## 4. 组件改动边界

- `ReaderDefault`：统一移动保留空间、背景 inert、面板 dialog 接线和阅读 canvas 焦点后备点。
- `ReaderTopBar` / `ReaderBottomBar`：工具栏 inert/aria-hidden、统一按钮原语、Lucide 图标与触发器引用。
- `SettingsSheet` / `TocDrawer`：44px 命中区、标题语义、关闭控件、统一分段控件和焦点入口。
- `PaginatedReader`：从共享变量读取保留区，保证测量、页容器和页码一致。
- `globals.css` / tokens：只新增阅读器级几何、圆角、阴影、focus-visible 和 reduced-motion 规则；不建立第二套全局设计系统。
- 测试：优先纯行为/组件测试；Playwright 验证真实视口、键盘与触控结果，不以 class 快照替代用户结果。

## 5. 状态、错误与兼容

- 所有改动为 `replay_safe` UI 状态变更，不写新持久化字段，不迁移现有阅读设置。
- `activePanel` 仍是唯一面板状态源；面板切换必须先完成前一面板的焦点清理，再激活下一面板。
- 若焦点目标不存在，面板容器以 `tabIndex=-1` 接收焦点；若焦点归还失败，阅读 canvas 接收焦点，不抛运行时错误。
- 不支持 `inert` 的环境仍由 `aria-hidden`、Tab 管理和事件守卫保证不可操作；类型层面使用 React 支持的 inert 属性，不引入 polyfill。
- 字体、主题、页模式、行距、段距、字距和自动切章设置的现有默认值与存储格式保持兼容。

## 6. 验证与验收

### 自动验证

- 单元/组件：焦点首入、Tab 循环、Shift+Tab、Escape、焦点归还、隐藏工具栏不进入 Tab、44px 控件合同、面板切换。
- Playwright 手机：375×812、390×844；滚动与分页分别验证菜单显隐、首末正文/页码不遮挡、目录/设置/进度可单手操作。
- Playwright 横屏与桌面：844×390、1024×900；无横向溢出、面板不超出可视区域、桌面既有侧栏路径不退化。
- 键盘：从阅读 canvas 打开各面板，焦点保持在面板内，Escape 返回触发按钮；隐藏菜单按钮不可聚焦。
- reduced-motion：菜单与面板状态立即稳定，无依赖动画结束事件的功能逻辑。
- 回归：TASK-0402 分页/连续滚动 E2E、reader-core、Web lint/type、生产构建与控制包 resume。

### 人工检查

- 舒适：正文不被控件压迫，菜单出现后仍能读到当前行与页尾。
- 低干扰：无意义动效和强阴影明显减少，工具栏隐藏后正文成为唯一主角。
- 单手易用：常用目标无需精确点按，关闭与返回始终可达。
- 视觉一致：图标基线、字重、圆角、文案和反馈在手机/桌面及明暗主题下属于同一体系。

每项按 PHASE-04 量表至少 4/5；该结果只证明 TASK-0403 候选，不提前证明 TASK-0404、PHASE-04、长期舒适度或 Goal 完成。

## 7. 回滚与非目标

- 实现按共享原语、接线、视觉 token 三层提交；任一层回归可独立回退，不接触阅读数据。
- 若统一 dialog 行为造成不可接受兼容问题，先回退到各面板局部焦点守卫，不回退 44px 触控和遮挡修复。
- 本轮不做全站 UI 重构、书架视觉更新、藏经阁、PWA 离线扩张、同步、VPS 部署或新的阅读手势。
